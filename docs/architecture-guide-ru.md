# Musubi Kairo: как читать архитектуру

28.09.2026. Пояснение к [архитектурному предложению 0.2](architecture.md).
Английский документ определяет предлагаемые правила; эта страница помогает
оценить их замысел и цену. Это проект для обсуждения, ещё не принятый стандарт.

## Главная конструкция

У проекта есть долговечное состояние: цель, полномочия участников, предложения,
позиции, решения, результаты и незавершённые обязательства. Любой агент может
закончить сессию; работа проекта от этого не исчезает. Новый участник получает
ограниченный по размеру актуальный контекст и ссылки на необходимые основания.

Координатор проверяет право на изменение и фиксирует результат. Планирование,
мышление, инструменты и личная память остаются у участников. Единое хранилище
решений не означает единственного управляющего AI.

## Какие вопросы документ решает конкретно

1. **Что считается решением.** В первом профиле владелец проекта принимает
   предложение после поддержки назначенных рецензентов. Их молчание, отказ или
   просьба уточнить блокируют принятие. Возражения остальных требуют ответа и
   сохраняются даже при отклонении. Другие способы принятия решений возможны
   как отдельные профили.
2. **К чему относится согласие.** К точной версии предложения, цели, правил,
   полномочий и исходных материалов. Поддержка прежнего текста автоматически
   не переносится на новый. Одобрение ещё не означает публикацию или проверку.
3. **Что происходит при смене цели.** Старые результаты сохраняются, но прежние
   разрешения больше не дают права публиковать новые изменения. Продолжение
   требует явного пересмотра работы и новой оценки.
4. **Как передавать работу.** У попытки есть исполнитель и поколение владения.
   Прежняя попытка завершается, новая получает другое поколение. Вернувшийся
   исполнитель не может записать результат от имени отозванной попытки.
5. **Что делать с потерянным ответом.** Повтор одной команды возвращает прежнюю
   квитанцию. После удаления квитанций сохраняется граница закрытой эпохи:
   старая команда отклоняется, а не выполняется заново.
6. **Что считать завершением.** Нужна проверка конкретного результата по
   указанным критериям. Законченный вызов модели или сохранённый файл этого
   не доказывает.

## Самый важный выбор реализации

Для первого строгого профиля предлагается управляемая версия документа:
содержимое неизменно, а указатель на текущую версию меняется одной транзакцией
вместе с решением, состоянием попытки и квитанцией. Это позволяет точно определить
момент публикации и восстановление после сбоя.

У этого решения есть цена: файл в редакторе становится представлением или
экспортом управляемой версии. Его синхронизация — отдельная операция. Если
команде нужен существующий Git-репозиторий или обычный файл как главный источник,
потребуется отдельный адаптер с честно описанными гарантиями. Проверить право,
а потом обычной записью заменить файл недостаточно: между действиями возможна гонка.

Во внешних системах бывает неизвестный исход: действие прошло, а подтверждение
потерялось. Архитектура требует выяснять результат; автоматический повтор может
создать второй эффект. Такое состояние остаётся видимым и может блокировать работу.

## Масштаб и долгий срок жизни

Все служебные данные остаются под `.kairo/`. Большие объекты готовятся вне коротких
транзакций. Агент получает относящиеся к его работе задачи и основания; весь журнал
не подаётся ему в контекст. Снимки состояния, изменения после снимка и адресный поиск
позволяют продолжать работу без полного перечитывания истории.

Архивирование сохраняет необходимые основания действующих решений и открытых
возражений. Производные резюме можно перестроить; потерянные доказательства нельзя
выдать за восстановленные. Безграничный объём незавершённых обязательств требует
растущего хранения — это ограничение названо прямо.

Восстановление из резервной копии создаёт новое поколение записи проекта.
Старые команды и курсоры перестают подходить. При этом идентичность проекта и
исторические ссылки сохраняются. Две живые копии одного хранилища не объявляются
репликами: старый писатель должен быть остановлен или технически отстранён.
